# Quartz 5 双分支工作指南

仅适用于新版。

## 1. 命令速查

```bash
# 切换到项目目录
cd E:\图书馆\quartz

# 本地预览（构建后自动打开浏览器）
python update_site.py --serve

# 正式发布（构建后推送到 deploy 分支）
python update_site.py --push

# 组合使用：构建 → 预览 → 推送
python update_site.py --serve --push

# 指定端口预览
python update_site.py --serve --port 9000

# 指定项目路径（不在项目目录时）
python update_site.py --path "E:\图书馆\quartz" --serve
```

## 2. 日常编辑工作流（在 v5 分支）

**前提**：所有编辑操作必须在 `v5` 分支进行。

```bash
# 确认当前分支
git branch
# 输出应为：* v5

# 开始编辑（Obsidian 中操作）
# ... 修改内容 ...

# 本地预览查看效果
python update_site.py --serve
# 浏览器自动打开 http://localhost:8080

# 确认无误后，提交源码到 v5
git add -A
git commit -m "更新内容描述"
git push origin v5
```

## 3. 正式发布（推送到 deploy 分支）

```bash
# 一键发布（构建 + 推送）
python update_site.py --push

# 或分步执行
python update_site.py        # 仅构建
python update_site.py --push # 仅推送（基于上次构建）
```

**脚本自动执行的操作**：
1. 运行 `npx quartz build` 生成 `public/`
2. 进入 `E:\图书馆\.quartz-deploy` worktree
3. 切换到 `deploy` 分支并同步远程
4. 清空旧文件，复制新的 `public/` 内容
5. 提交并推送到 `origin/deploy`

## 4. 分支管理规则

| 分支 | 用途 | 操作方式 | 禁止行为 |
|------|------|----------|----------|
| `v5` | 源码+设定备份 | 日常 `git commit` + `git push` | ❌ 不要手动 `git add public` |
| `deploy` | 发布分支（GitHub Pages） | 仅通过脚本 `--push` | ❌ 不要手动编辑此分支 |

## 5. 故障排查

### 问题：`webbrowser` 模块报错
- **原因**：Python 版本或环境缺失标准库
- **解决**：确认使用的是 Python 3.11+（`python --version`）

### 问题：worktree 目录已存在但状态异常
- **原因**：上次脚本中断导致 `.quartz-deploy` 残留
- **解决**：
  ```bash
  cd E:\图书馆\quartz
  git worktree remove ../.quartz-deploy
  # 然后重新运行 --push
  ```

### 问题：推送被拒绝（deploy 分支有冲突）
- **原因**：deploy 分支历史与脚本不一致
- **解决**：
  ```bash
  cd E:\图书馆\.quartz-deploy
  git reset --hard origin/deploy
  ```
  然后重新 `--push`。

### 问题：`quartz.config.yaml` 找不到
- **原因**：不在项目目录且未指定 `--path`
- **解决**：使用 `--path "E:\图书馆\quartz"` 或先 `cd` 到项目目录。

## 6. 重要提醒

- **不要手动编辑 `.quartz-deploy` 目录**：它是脚本自动管理的 worktree。
- **不要在 v5 分支提交 `public/` 目录**：该目录由脚本构建生成，已加入 `.gitignore`（如有）。
- **GitHub Pages 配置**：首次部署后，在仓库 Settings → Pages 中将 Source 设置为 `deploy` 分支。

---

如需调整脚本参数（如默认端口、worktree 路径），可直接编辑 `update_site.py` 顶部的 `DEFAULT_*` 常量。
